this system was meant to flow like below but also supposed to sync only points and id(telephone number) for completed orders to firebase which acts as our loyalty program engine but while avoiding duplicates and unnecessary calls to the firebase. New users should be registered automatically
🍽️ Orders Flow
New Orders:
•	Menu items fetched from menu_items table
•	Items added to context-driven currentOrder state
•	Submitted as pending to orders and order_items
Review & Approval:
•	Review.tsx polls pending orders every 3s
•	Staff can approve (trigger print) or decline (store reason)
•	Status updated in SQLite
Approved Orders:
•	Filtered view showing approved transactions
•	Printable receipts available via ReceiptPayload

🔧 Admin Features
•	View and export monthly CSV reports
•	Future scope: Add/remove menu items, manage staff, loyalty programs

📤 CSV & Print Services
•	useMonthlyCSVExport.ts: Hook triggered at app start to run backup logic
•	printer.ts: Formats and sends receipt data to a paired thermal printer

📊 Data Models (from types.ts)
Table	Key Fields
orders	id, totalAmount, status, declineReason
order_items	id, menuItemId, quantity, unitPrice
customers	id, phone, points
staff	id, name, pin, role
